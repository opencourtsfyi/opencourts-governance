# Review Process

## Goals

- Keep changes safe, reversible, and understandable.
- Maintain a low-friction path for volunteers.

## PR Expectations

- Each PR should explain **what** and **why**.
- Link related issues and ADRs where relevant.
- For governance/design changes, request review from maintainers.

## Decision Records

If a PR changes architecture or introduces new standards, add/update an ADR in `design/adr/`.
