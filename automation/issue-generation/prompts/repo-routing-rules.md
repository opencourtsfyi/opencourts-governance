# Repo Routing Rules

These rules help decide where an extracted task belongs.

## Governance vs Implementation

- If the change is about **policy, charter, decision-making, roles, or process** → keep it in this repo.
- If the change is about **code for the data portal / ingestion / infrastructure** → route to the implementation repo(s).

## Suggested Routing Tags

- `governance`: charter + policies + contribution process
- `design`: SRS/SDD/diagrams/ADRs
- `automation`: issue generation and related workflows

## Notes

When in doubt, open an issue here with a link to the relevant document section and ask maintainers to route it.
